# 1. 产品概述

## 1.1 背景

DSH 已能发现并在需要时加载 Agent Skill，但控制粒度是"单个技能 + 声明式 frontmatter"。当技能数量到几十上百，真实工作单位不再是"某个技能"，而是"一类活儿"——前端工程、内容生产、视频制作、工程维护。这类活儿通常需要 5–15 个技能覆盖规划、执行、验证、交付，其中一部分是跨工位共用的。

用户当前只有三种手段：改 frontmatter（改文件）、换 Agent Preset（静态组合，需重组）、逐个开关（第三方插件做法）。三者都不支持"多个工位同时在场、彼此共享技能、随时切换、且不污染原始文件"。

织音补的是这一层：**在运行时把一组技能包编译成模型可见的目录与授权面**。

## 1.2 产品定义

织音是 DSH Web 插件，提供五项能力：

1. **观测**：读取当前 Agent Scope 的技能目录（含完整性状态），不自行扫描磁盘、不复制正文。
2. **编配**：把技能组织成有明确职责的**技能包**；一个技能可属于多个包（多对多）。
3. **合奏**：同时启用多个包，按"并集 + 常驻 + 排除"计算意图集合。
4. **组合**：把常用包组合保存为**组合**，支持替换应用与叠加应用。
5. **投影**：把意图编译成模型目录、**skill** 工具白名单与用户命令响应，并显示"意图与观测"的差异。

## 1.3 核心价值

- 把"逐个找技能、逐个开关"变成"按活儿一键切换"。
- 把互斥的角色切换变成可叠加的多包合奏，同时保留共享技能的单一来源。
- 让"启用多少"变成可计量的成本（目录字符预算），而不是越多越好的直觉。
- 让"为什么这个技能在/不在"可追溯到具体包、具体规则、具体观测时刻。
- 全程不改写原始技能文件、不复制正文、不改 DSH 核心。

## 1.4 边界一句话

**织音决定"模型此刻看得见什么"，不决定"技能本身是什么"。**

# 2. 可行性前提与接入点（本版核心章节）

## 2.1 平台事实

以下为 DSH 官方文档明确记载的行为，是后续全部设计的硬约束（来源见附录 B）：

| 编号 | 事实 | 对产品的含义 |
|---|---|---|
| **F1** | 技能注册表是**宿主层 + 每作用域层**的分层结构；读取时合并全局层与观察者作用域链，**最近的层同名直接胜出**；rank 只在**同一层内**决定重复名的胜负 | 任何"用低 rank 全局代理压住所有技能"的方案，都压不住靠更近层提供的技能 |
| **F2** | **registerProvider** 只能把 provider 注册进**调用上下文所在**的层；没有"往别的 Agent 的层里写"这一动作 | 全局插件无法在运行时把策略注入任意 Agent 的作用域 |
| **F3** | **get()** 每次把胜出候选的不透明 locator 交回**该候选所属的** provider；正文不进注册表缓存 | 谁赢得名字，谁就必须能交出正文与资源基址 |
| **F4** | 技能摘要里的双调用策略是**唯一授权闸门**：模型工具在加载**前**检查一次，加载**后**再检查一次 | 控制摘要 = 控制模型面；不需要改正文 |
| **F5** | 模型目录只含 **name + description**（描述上限默认 500 字符），且成员/描述/可见性变化会**追加**一条 replacement 目录到会话历史；空目录会显式退役旧名字 | 切换有上下文成本，且是追加语义，不是覆盖 |
| **F6** | 用户面有**两条独立通道**：会话内 **/name** 手势（由消费者监听已认领的用户消息）+ GUI 斜杠菜单（由宿主服务 **ctx.sessionSkillCatalog** 读注册表） | 一个"用户可用"布尔覆盖不了两个实现者 |
| **F7** | 消费者插件可全局挂载，也可挂在**单个 Agent 的组合**里；同名**作用域内**工具会遮蔽全局工具，被遮蔽的消费者会自行退场并退役其目录 | 提供了一条**官方认可**的接管路径，无需修改 DSH 或删插件 |

## 2.2 三条推论

**C1｜Provider 侧只能做加法。**
要"隐藏"一个技能，必须让一个同名候选胜出；同名候选胜出，**get()** 就归你；而你没有别人的正文与 locator。因此 Provider 侧的减法只有两种结局：复制正文（违反"不复制"红线），或把 **get()** 打断（违反"不破坏可信消费者"）。**这不是"某些第三方 Provider 不支持"，而是 API 形状决定的。**

**C2｜产品语义住在消费侧。**
"模型看到什么、允许加载什么"由消费者实现（目录发布 + **skill** 工具 + **/name** 手势）。注册表只回答"有哪些技能、正文在哪"。所以正确的接入点是**替换投影器**，不是**替换生产者**。

**C3｜没有单一接缝能覆盖全部生效面。**
消费者接管能覆盖模型目录、**skill** 工具、会话内 **/name**；GUI 斜杠菜单由另一个宿主服务读取注册表，默认不受控。产品必须**显式声明生效面矩阵**，不允许用一个"已启用"状态暗示四面齐平。

## 2.3 主路：目录主权（Catalog Sovereignty）

织音由两个挂载点组成：

1. **宿主插件（全局）**：数据、意图服务、观测服务、设置页、远程接口。只读注册表，不注册任何 provider。
2. **投影器（每个受管 Agent 预设的常驻组合内）**：注册同名 **skill** 工具，遮蔽 DSH 默认消费者，自行发布目录与处理 **/name**；正文加载一律委派 **ctx.skills.get()**。

由此得到的性质：

- **零 registry 变更**：切换合奏不改注册表，不触发 **skills/change** 风暴，不产生 provider 反复注册/注销的缓存抖动。
- **正文零复制**：一切加载走 **get()**，资源基址保持原样。
- **真实时**：生效点在 pre-step，下一个模型步骤即生效；不承诺回溯已组装的请求。
- **按作用域正确**：投影器天然知道自己挂载在哪个 Agent 组合里，读意图时带上自己的 **cwd + scope**。
- **可卸载**：移除组合项即恢复默认消费者；宿主持久化数据不受影响。

代价必须写在明处（见 §2.6）：需要一次性的组合变更；要承担上游消费者的语义对齐；GUI 菜单可能漂移。

## 2.4 M0 门禁（四问 + 六项回归）

M0 交付一个最小投影器原型与自动化测试。**四问全部有证据结论，才可进入 M1；任一问失败，按 §2.5 选分支。**

**Q1｜同名作用域工具能否稳定接管？**
在受管预设的常驻组合内注册同名 **skill** 工具后：
- 默认消费者是否确实退场，并退役其旧目录？
- 接管当步是否出现"空目录 + 新目录"两条消息？可接受上限为 1 个模型步骤。
- 工具 schema、错误文案、**/name** 手势行为是否保持一致？

**Q2｜正文与资源是否无损？**
- 被过滤掉的技能，**ctx.skills.get()** 对可信消费者是否仍返回完整正文（应保留）。
- 保留下来的技能，加载后 **resourceBase** 相对资源路径是否仍然有效（目录型、URL 型、opaque 型各一例）。

**Q3｜目录成本与发布语义是否可控？**
- 一次切换追加的目录字符量是否可测、可预算、可按批量提交合并为一次投影？
- 目录 digest 是否只对条目与完整性敏感，不因渲染差异反复重发？

**Q4｜GUI 斜杠菜单能否覆盖？**
- 能否在 Profile 组合内替换 **ctx.sessionSkillCatalog**？若不能，漂移（菜单列出已停用技能、使用后无响应）是否可被明确提示并写进已知限制？

**六项回归（任一失败即门禁不通过）：**

1. 插件卸载后 DSH 恢复默认消费者与原技能行为，无残留目录。
2. 两个 Agent 并发、不同 **cwd**，各自投影互不串台。
3. 运行中新增/删除技能：目录更新，且不因一次不完整观测清空合奏。
4. 预设切换、Agent 销毁重建后，投影器重新挂载并取到当前意图。
5. 全过程不写入、不重命名、不删除任何技能文件，不产生仓库脏改动。
6. DSH 重启后，意图、组合、技能包、投影日志全部恢复。

**通过条件：** 四问均有书面结论与可复现脚本；六项回归全绿。**不得以"隐藏成功"作为接管成功的证据**——必须同时验证正文加载、**/name** 响应与空目录退役。

## 2.5 三条产品分支（预承诺）

M0 结束必须落到其中一条，不允许"再研究一下"：

| 分支 | 触发条件 | 交付形态 | 代价 / 对外话术 |
|---|---|---|---|
| **B1 目录主权**（主路） | Q1、Q2 通过（Q4 可失败） | 完整产品：运行时合奏 + 组合 + 预算 + 冲突 | 需一次性组合变更；GUI 菜单漂移须文档化 |
| **B2 组合编译器** | Q1 失败，但可写预设组合 | 每个组合生成一个 Agent 预设；切换 = 换预设 | 无运行时切换；卖点从"合奏"改为"一次性生成正确组合"；话术不得出现"实时" |
| **B3 只读诊断** | Q1、B2 均不可 | 只交付观测、审计、建议与预算报告 | 不写任何可用性；话术不得出现"启用/停用/控制" |

**决策树：**

~~~text
Q1 接管失败?
├─ 否 → Q2 正文无损?
│        ├─ 是 → B1（Q4 失败则标注菜单漂移）
│        └─ 否 → 退回 Provider 侧? 否 → B2
└─ 是 → 可写预设组合?
         ├─ 是 → B2
         └─ 否 → B3
~~~

B2 / B3 的对外表述、安装引导、设置页文案必须由本 PRD 预先确定（见附录 A），不得在实现期临时决定。

## 2.6 已知限制（必须写进产品，不得隐藏）

1. **GUI 斜杠菜单可能漂移**：菜单由宿主服务读注册表，可能列出已停用技能；点击后由投影器拒绝，需给出明确提示。
2. **需要一次组合变更**：把投影器加入受管 Agent 预设的常驻组合，是一次显式、可逆的安装动作；未加入预设时，织音只具备只读能力。
3. **上游语义对齐成本**：目录模板、digest、空目录退役、不完整警告、防重复加载规则都要与上游保持一致，属持续维护项。
4. **多消费者共存**：若用户同时安装其他技能消费者，同名工具遮蔽关系需实测，可能出现一方静默失效。

## 2.7 待核实断言（差异化论证的薄弱点）

| 断言 | 为什么重要 | 负责人 | 截止 |
|---|---|---|---|
| 现有社区插件均为"排他角色切换"，不支持多包叠加 | 这是本产品**唯一**的差异化论据 | 产品 | M0 结束前 |
| 上述插件不支持共享技能的引用计数解释 | 决定"可解释"是否算差异点 | 产品 | M0 结束前 |
| DSH 预设组合可由第三方插件写入 | 决定 B2 是否可行 | 技术 | M0 结束前 |

未按期核实，则 §4.1 的 G2/G3 降级为"体验改进"而非"差异化"。

# 3. 术语、语义与文案

## 3.1 术语（人话优先）

| 实际对象 | 主用词（UI 与文档） | 品牌别称（副标题/图标/日志） |
|---|---|---|
| 一个 Agent Skill | 技能 | 音符 |
| 一组承担同一职责的技能 | **技能包** | 声部 |
| 多个技能包同时启用 | **当前生效** | 合奏 |
| 保存的包组合 | **组合** | 乐谱 |
| 被多个包引用的技能 | 共享技能 | 共享音符 |
| 已发现但不在任何包内 | 未编配技能 | 未编配音符 |
| 用户强制始终可用的技能 | 常驻技能 | 常驻音符 |
| 明确从当前生效中剔除的技能 | 已排除技能 | — |
| 当前实际可加载的技能集合 | 生效技能 | 生效音符 |

**规则：** 一级导航、按钮、表单标签**只用主用词**；品牌别称只出现在页面副标题、空态插画、日志与代码注释中。**"声部（技能包/工位）"这类三词并列的写法废止**——它把"旋律线"与"地点"两个不相容隐喻焊在一起。

## 3.2 文案原则

- 用户动作说人话：创建技能包、启用、停用、排除、保存组合、应用组合。
- 状态说人话：当前生效 / 未接管 / 观测不完整 / 正在应用 / 已排除 / 源限制。
- 不使用"音节""乐章"等未被定义的词。
- 技术文档与代码使用 Skill、SkillPack、Score、Intent、Projection、Observed，不强迫开发者用诗性表达。
- 任何"已启用"字样必须能回答：在**哪个生效面**启用（模型目录 / 工具 / 命令 / 菜单）。

## 3.3 三态不变式（本产品的核心）

~~~text
Intent      用户意图：启用的包、常驻、排除。唯一可写对象。
   ↓ 纯函数投影（带 cwd + scope + 观测）
Projection  本次投影产物：条目、授权、目录字符数、警告、digest。可重放。
   ↓ 发布 / 加载
Observed    实际观测：注册表快照 + complete + 生效时刻。只读。
~~~

规则：

1. **UI 永不显示"应该"**：所有数字、徽标、清单默认来自 Observed；Intent 只用于解释"你为什么期望这样"。
2. **差异 = Observed − Projection**，修复动作只有"重投影"，不允许直接改 Observed。
3. **Projection 是纯函数**：同一 (Intent, Observed, 配置) 必得同一结果，有单元测试。
4. **观测不完整时**：保留上一次成功的 Observed，Projection 标记 degraded，不执行破坏性变更。

# 4. 目标与非目标

## 4.1 目标（Goals）

- **G1 按活儿编组。** 技能包以工作职责为边界，覆盖该职责的完整流程，而非按单步操作拆分。
- **G2 多对多共享。** 同一技能可属于任意多个包；包之间不互斥。
- **G3 多包合奏。** 多个包同时启用，实时计算并集，重复技能只计一次。
- **G4 安全启停。** 停用包只撤销该包的贡献；仍被其他启用包或常驻引用的技能继续生效。
- **G5 可编排的最小差异。** 支持"这套里不要 X"的排除，不需要为一次临时需求去改共享包。
- **G6 可解释、可计量。** 任一技能可追溯提供者；任一合奏可报出目录字符成本与冲突。
- **G7 尊重 DSH。** 只用公开能力：技能注册表、消费者、客户端插槽、存储域；不改核心、不改写技能文件、不复制正文。

## 4.2 非目标（Non-goals）

- 安装/卸载/升级 DSH 插件或 MCP Server。
- 编辑技能正文、frontmatter、脚本或资源。
- 技能市场、GitHub 同步、内容审计平台。
- 用 LLM 判断"用户现在在干什么"并自动切换（不引入隐式行为）。
- 自动为每个技能生成一个包。
- 强制统一预设工位。
- 跨 Profile 同步、云账号、多人协作（首版）。
- 自动消解技能之间的语义冲突（只做检测与提示，不做改写）。

## 4.3 成功判据（可测）

| 编号 | 判据 | 测量方法 | 目标 |
|---|---|---|---|
| **K1** | 从安装到第一次成功启用一套技能包 | 新手任务计时（n≥5） | ≤ 5 分钟，无需读文档 |
| **K2** | 在 100 技能 / 10 包规模下切换工作场景 | 点击次数与耗时 | ≤ 3 次点击、≤ 10 秒 |
| **K3** | 因误停共享技能导致的任务失败 | 30 次切换 + 任务回归 | 0 次 |
| **K4** | 典型 3 包合奏的目录字符量 | 估算值与实测值偏差 | ≤ 预算（默认 8000 字符）的 80%；告警覆盖 100% |
| **K5** | UI 与真实目录不一致的窗口 | 切换后逐步比对 | ≤ 1 个模型步骤，且 100% 可检测 |
| **K6** | 崩溃/重启后意图与组合恢复率 | 断电式重启测试 | 100% |
| **K7** | 无法由织音控制的生效面占比 | 生效面矩阵自检 | 必须在 UI 显式标注，占比为 0 时方可宣称"完整控制" |

# 6. 核心语义

## 6.1 五个对象

| 对象 | 归属 | 可变性 |
|---|---|---|
| 技能（Skill） | DSH 注册表 | 只读观测 |
| 技能包（SkillPack） | 织音 | 用户可写 |
| 组合（Score） | 织音 | 用户可写 |
| 意图（Intent） | 织音 | 用户可写，唯一真相源 |
| 投影（Projection） | 织音 | 派生，不独立写 |

## 6.2 意图集合

设：

- **S(p)**：包 p 的技能名集合
- **A**：启用的包集合
- **R**：常驻技能集合
- **X**：排除技能集合
- **E**：生效技能集合（意图层）

~~~text
E = ( R ∪ ⋃ S(p) ) \ X        p ∈ A
~~~

~~~ts
const e = new Set(intent.alwaysOnSkillNames)
for (const partId of intent.activePackIds) {
  for (const name of parts[partId]?.skillNames ?? []) e.add(name)
}
for (const name of intent.excludedSkillNames) e.delete(name)
~~~

规则：

1. 一切按技能**规范名称**去重；同名即同一技能，不因来源不同计为两个。
2. **X 优先于 R**：同一技能同时在常驻与排除中，视为配置矛盾，按"不生效"处理并在 UI 报错要求二选一。
3. 排除是**合奏层**的动作，不修改任何包的成员关系。

## 6.3 引用计数与成员判定

~~~text
providers(s) = |{ p ∈ A : s ∈ S(p) }|
isMember(s) = ( providers(s) > 0 ∨ s ∈ R ) ∧ s ∉ X
~~~

- **providers(s) > 1**：共享技能，UI 显示全部提供者。
- **providers(s) = 0 且 s ∈ R**：常驻技能。
- **s ∈ X**：已排除，即使 providers > 0 也不生效。
- 生效集合的元素个数按**集合基数**计，不按引用次数计。

## 6.4 停用包的正确行为

设 A = {React, UI, Git, Testing}，B = {Git, Testing, Python, Docs}，同时启用。

~~~text
启用 A+B：E = {React, UI, Git, Testing, Python, Docs}
停用 A ：E = {Git, Testing, Python, Docs}
~~~

**禁止实现为"关闭包 A → 批量关闭 A 的全部技能"。** 正确顺序：更新 A → 重算 E → 求与上次投影的差异 → 只对差异项发布变更。

## 6.5 单个技能的可用动作

| 动作 | 作用域 | 结果 |
|---|---|---|
| 加入/移出一个包 | 包 | 改变包编制；若包在启用中，立即重投影 |
| 设为/取消常驻 | 意图 | 与包无关地保持/不保持生效 |
| 排除/取消排除 | 意图（合奏层） | 在本次合奏中强制剔除/恢复该技能 |
| 直接"关闭" | — | **不提供**。关闭必须落在包、常驻或排除三者之一，保证状态可解释 |

## 6.6 四闸门矩阵（生效面）

一个技能对外的最终呈现 = 合奏成员 × 源允许模型 × 源允许用户：

| 合奏成员 | 源允许模型 | 源允许用户 | 模型目录 | **skill** 工具 | **/name** | 说明 |
|---|---|---|---|---|---|---|
| 是 | 是 | 是 | 列出 | 可用 | 可用 | 正常工作 |
| 是 | 是 | 否 | 列出 | 可用 | 不可用 | 仅模型面（源限制） |
| 是 | 否 | 是 | 不列 | 不可用 | 可用 | 仅用户面（源限制） |
| 是 | 否 | 否 | 不列 | 不可用 | 不可用 | 仅可信 **get()** 可见，UI 标"内部可用" |
| 否 | 任意 | 任意 | 不列 | 不可用 | 不可用 | 未编配 / 未启用 |
| — | — | — | — | — | — | 被排除：不列、不可用，并标"你排除了它" |

**规则：** 技能包启用**不会**放宽源的策略；最终状态取交集。UI 必须显示是哪个闸门关的，不允许只显示"已启用/已停用"。

## 6.7 冲突

**为什么需要：** 技能是指令文本，两个包的指令可能互相抵消（例如两个写作风格包、两个互相矛盾的流程包）。并集对冲突是沉默的。

- 技能包可声明 **conflictsWith: string[]**（包 ID 列表）。
- 应用/启用前检测：任一对冲突且同时启用 → **默认阻断**，列出冲突对与各自成员。
- 用户可显式"仍然应用"，记录 **conflictAck**（含时间、意图修订号、冲突对），不持久化"永久忽略"。
- 只做检测与提示，不做语义消解（不调用 LLM，不自动改成员）。

## 6.8 目录预算

模型目录的成本是可计算的：

~~~text
perSkillChars = min(length(description), catalogDescriptionMaxLength)   // 默认上限 500
catalogChars  = perSkillChars 之和 + 固定框架开销（约 200 字符）
~~~

- **预算默认 8000 字符**（可配），软阈值：达到 80% 提示，超过 100% 强提示但不阻断（阻断会诱使用户乱排除）。
- 合奏页同时显示：整份目录字符数 / 预算占比 / **每个包的目录成本**。
- 每次变更都会**追加**一份目录到会话历史；因此界面必须提供"修改后一次提交"，禁止把连续开关逐个提交（见 §11.5）。

## 6.9 三态一致性与修复

| 状态 | 判定 | UI 表现 | 修复动作 |
|---|---|---|---|
| synced | Observed 条目 = Projection 条目 | 正常 | — |
| pending | 已提交，下一 pre-step 未到 | "正在应用" | 等待 |
| degraded | Observed.complete = false 或结构不符 | 黄色徽标 + 上次成功时间 | 重试观测 |
| failed | 投影发布失败 | 红色徽标 + 保留上次成功投影 | 重试 / 回滚 |
| drifted | 观测与投影条目不一致（技能被外部改策略、来源切换） | 差异清单 | 重投影 |

## 6.10 初始化与默认策略

1. 首次进入：读取完整快照，检查 **complete**。
2. 默认**兼容模式**：不接管，不改任何可用性；只做观测与建议。
3. 用户创建第一套包/组合后，显式确认"由织音接管"：展示加入/退出/保持预览 + 目录预算 + 冲突检查。
4. 接管后，新发现且未编配的技能**不自动生效**，进入"未编配"。
5. 观测不完整时，保持上次成功投影（last-known-good），不批量停用。

# 7. 数据模型

## 7.1 技能引用（观测产物）

~~~ts
interface NoteRef {
  /** DSH 规范名，kebab-case，调用身份。 */
  name: string
  description?: string
  source?: string
  provider?: string
  path?: string
  /** 观测到的源调用策略，不等于最终状态。 */
  baseInvocation?: { modelInvocable: boolean; userInvocable: boolean }
  /** 观测到的资源基址，用于解释相对资源。 */
  resourceBase?: { kind: 'directory' | 'url' | 'opaque'; path?: string; url?: string; description?: string }
  observedAt?: string
  /** 是否由织音可控（消费者接管后恒为 true；只读来源为 false）。 */
  controllable: boolean
}
~~~

**身份规则：** 规范名即身份。来源、provider、路径只用于解释与诊断；同名多来源由注册表层规则裁决，织音**不得**把同名副本当作两个可分别启停的对象。技能失联时保留引用并标"暂不可用"，同名恢复后自动重新匹配。

## 7.2 技能包

~~~ts
interface SkillPack {
  id: string
  name: string
  /** 工位职责：什么时候该启用这个包。 */
  role: string
  skillNames: string[]
  /** 与其他包互斥（双向语义，应用前检测）。 */
  conflictsWith: string[]
  order: number
  createdAt: string
  updatedAt: string
}
~~~

约束：包内不允许重复成员；一个技能可属于任意多个包；包不拥有技能文件，不负责删除技能；改名不改 ID，不影响组合引用。

## 7.3 组合

~~~ts
interface Score {
  id: string
  name: string
  description?: string
  packIds: string[]
  order: number
  createdAt: string
  updatedAt: string
}
~~~

组合只保存包 ID 列表，应用时读取包的最新编制；应用前必须展示由此产生的差异。示例："全栈开发" = 前端 + 后端 + 数据库 + 交付；"公众号视频" = 内容生产 + 视频制作 + 视觉设计。

## 7.4 意图

~~~ts
interface EnsembleIntent {
  /** compat：不接管；orchestrated：由织音投影。 */
  mode: 'compat' | 'orchestrated'
  activePackIds: string[]
  alwaysOnSkillNames: string[]
  /** 合奏层排除，不修改任何包。 */
  excludedSkillNames: string[]
  /** 导出的最小单元，schemaVersion 一并导出。 */
  schemaVersion: number
  revision: number
  updatedAt: string
}
~~~

V1 决策：意图按 **DSH Profile** 持久化，同一 Profile 内的 Agent 共享同一意图，但**观测按各自 cwd + scope** 独立。工作区级与 Session 级覆盖属 P1。

## 7.5 投影

~~~ts
interface ProjectionEntry {
  name: string
  description: string
  modelInvocable: boolean
  userInvocable: boolean
  /** 提供该技能的启用包 ID（共享时多个）。 */
  providers: string[]
  excluded: boolean
  missing: boolean
}

interface Projection {
  intentRevision: number
  scopeKey: string
  cwd?: string
  entries: ProjectionEntry[]
  /** 对条目与完整性做摘要，用于判断是否需要重新发布目录。 */
  digest: string
  catalogChars: number
  warnings: Array<{ kind: 'conflict' | 'budget' | 'incomplete' | 'missing' | 'excluded-constant'; detail: string }>
  createdAt: string
}
~~~

## 7.6 持久化

- 使用 **ctx.storageDomain** 的 schema 校验域存储；逻辑表：**voice_packs**、**scores**、**ensemble_intent**、**projection_log**、**plugin_meta**。
- 不写入 Session Event Log；不把包配置注入模型上下文。
- 每次写入在持久化成功后才向 UI 返回成功；失败保留原状态并报错。
- 数据结构带 **schemaVersion**；迁移只做向前兼容，不允许静默丢字段。
- 不使用浏览器 localStorage 作为真相源；只允许缓存 UI 偏好。
- **P0 最小导出**：一键导出 JSON（包、组合、意图、排除、schemaVersion），导入时校验并列出缺失技能。

# 8. 信息架构与界面

## 8.1 入口

首版：**DSH → Settings → 织音**（客户端插槽注册）。不改造主侧栏，不新增独立窗口。侧栏快捷入口属后续版本，不得因此产生第二套 UI 状态。

## 8.2 四个一级页面（人话导航）

| 页面 | 副标题（品牌别称） | 主要任务 |
|---|---|---|
| **当前生效** | 合奏 | 看现在模型能用什么、成本多少、有什么冲突，并启用/停用包 |
| **技能包** | 声部 | 按职责创建与维护技能包 |
| **全部技能** | 音符库 | 检索技能、看来源与策略、看归属、找未编配 |
| **组合** | 乐谱 | 保存与复用包组合 |

导航标签只用主用词；副标题小字保留品牌表达。

## 8.3 当前生效页（默认首页）

**顶部状态区（全部来自 Observed）**

- 模式：未接管 / 已编排 / 降级（含原因）
- 当前 Agent 与工作区（**因为数字依赖上下文，必须显示**）
- 生效技能数（去重后）· 共享技能数 · 未编配数 · 已排除数
- 目录字符数 / 预算占比
- 观测完整性 + 上次成功时间 + 同步状态徽标

**包选择区**

- 多选开关（不是单选）；每张卡片显示：名称、职责、成员数、生效成员数、共享成员数、**目录成本**、冲突标记
- 允许"批量修改后一次提交"：开关先记录为待提交变更，点"应用"后一次投影
- 与本页状态完全一致的组合会显示"当前 = 组合：X"

**生效技能区**

- 去重清单；每项显示提供者（如"Git · 前端工程 / 交付"）
- 徽标区分：共享 / 常驻 / 排除 / 源限制（模型或命令）/ 失联
- 点击展开：来源、provider、路径、源策略、四个闸门的实际开合

**警告区**

- 冲突对（含"仍然应用"入口）
- 预算超限（列出成本最高的 5 个技能）
- 观测不完整（保留上次成功状态的时间戳）

## 8.4 技能包页

卡片：名称、职责、成员数、共享成员数、目录成本、启用状态、编辑/复制/删除。
编辑：搜索并多选加入；勾选已有音符；显示该技能还属于哪些包；拖拽排序（仅影响展示）；声明冲突包。
保存时若包在启用中：先预览合奏变化与预算变化，持久化成功后同步投影。
创建流程不要求用户先理解音乐术语：按钮文案为"新建技能包"。

## 8.5 全部技能页

- 按名称/描述搜索；按来源、状态、所属包过滤
- 只看未编配 / 只看共享 / 只看失联
- 显示源 **modelInvocable** / **userInvocable**
- 快速加入一个或多个包；设为/取消常驻；排除/取消排除（仅在本合奏生效）
- 显示注册表当前胜出的 provider、source、path
- 不可控来源展示只读原因（若出现）

## 8.6 组合页

卡片：名称、描述、包含的包与成员数、合并去重后的预计生效数、**预计目录字符数**、与当前生效相比的新增/退出/保持、冲突状态。
操作：应用（**替换**）、叠加、复制、编辑、删除。

**语义必须写死在按钮上：**

- "应用组合" = 将 **activePackIds** 原子替换为组合内的包集合（排除集是否保留：默认**保留**，并在确认框说明）。
- "叠加到当前生效" = 追加，不替换。
- 两者都必须先出差异预览；替换操作不得静默发生。

## 8.7 状态机与空/错态

~~~mermaid
stateDiagram-v2
  state "未接管（兼容模式）" as Compat
  state "接管中" as Applying
  state "已编排" as Orchestrated
  state "降级" as Degraded
  state "失败" as Failed
  [*] --> Compat
  Compat --> Applying: 用户确认接管（预览 + 预算 + 冲突检查）
  Applying --> Orchestrated: 投影发布成功
  Applying --> Failed: 发布失败
  Orchestrated --> Degraded: 观测不完整 / 外部策略变化
  Degraded --> Orchestrated: 重投影成功
  Failed --> Orchestrated: 重试成功
  Failed --> Compat: 用户撤销接管
  Orchestrated --> Compat: 用户撤销接管
~~~

| 场景 | 表现 | 可执行动作 |
|---|---|---|
| 一个技能都没有 | 空态说明 + 检查技能目录位置的引导 | 重新观测 |
| 一个包都没有 | 引导创建第一个包，或从模板开始 | 新建 / 用模板 |
| 观测不完整 | 黄色徽标 + 上次成功时间；不执行破坏性变更 | 重试；查看已读到的部分 |
| 投影发布失败 | 红色徽标；保留上次成功投影 | 重试 / 回滚 / 撤销接管 |
| 预算超限 | 橙色条；列出成本最高的技能 | 排除 / 精简描述 / 拆分包 |
| 包冲突 | 阻断应用；列出冲突对 | 停用其一 / 仍然应用（留痕） |
| 技能失联 | 灰显"暂不可用"；成员关系保留 | 替换引用 / 等待恢复 |
| 同名来源切换 | 显示"来源已变更"+ 新旧 provider | 确认 / 忽略 |
| 并发写入冲突 | 提示"配置已在别处修改" + 刷新 | 刷新 / 强制覆盖（需确认） |
| GUI 菜单漂移 | 菜单中标注"未在当前生效中"；点击时给出解释 | 见 §12.2 |

## 8.8 无障碍与响应式

- 开关同时提供文字状态（"已启用"/"已停用"），不仅依赖颜色。
- 全键盘可达；焦点顺序与视觉顺序一致；差异预览可被屏幕阅读器逐项读出。
- 窄屏：卡片单列，差异预览用抽屉；不得出现横向溢出。
- 首版中文，代码保留英文 locale 结构。

# 9. 关键流程

## 9.1 首次安装（兼容模式）

1. 安装插件，重启/加载 Web Profile。
2. 读取当前 Agent 的技能快照，检查 **complete**。
3. 不完整则展示警告与已读到的内容，不把"没读到"当成"没有技能"。
4. 全程不改变任何可用性；页面显示"尚未接管"。
5. 引导创建第一个包（或说明"只想看目录也可以"）。

## 9.2 接管（切到已编排）

1. 用户点"由织音接管当前生效"。
2. 系统展示：将加入 / 将退出 / 保持 / 已排除 / 冲突 / 目录预算。
3. 若未把投影器加入预设常驻组合，先给出一次性安装指引（含"为什么需要"）。
4. 用户确认 → 写意图（mode: orchestrated）→ 发布首次投影。
5. 显示"已应用，自下一个模型步骤起生效"。

## 9.3 创建技能包

1. 新建技能包 → 填写名称与职责。
2. 搜索并添加技能；若该技能已属其他包，显示"共享技能"提示，不阻止。
3. 声明冲突包（可选）。
4. 保存；包默认不启用。

## 9.4 多包合奏

1. 在当前生效页启用"前端工程"（进入待提交）。
2. 再启用"交付"（仍为待提交，界面显示"2 项待应用"）。
3. 点"应用"→ 一次投影 → 目录追加**一条**。
4. 展示最终清单与每项提供者。

## 9.5 停用含共享技能的包

1. 停用"前端工程"。
2. 重算 providers 与 E。
3. 仅 providers = 0 且不在常驻、未被排除恢复的技能退出。
4. 展示"退出 / 因其他包保留"两组。

## 9.6 保存与应用组合

1. 当前生效页点"保存为组合"，填名称与说明（保存当前启用包集合）。
2. 应用组合：先算差异 + 预算 + 冲突，再确认。
3. 默认替换；排除集默认保留（可勾选"同时清空排除"）。
4. 成功后写投影日志，可回滚到上一版意图。

## 9.7 排除单个技能

1. 在"全部技能"或"当前生效"中点"排除"。
2. 显示影响：该技能从本次合奏退出，但仍在所属包内。
3. 确认 → 重投影；技能标记"已排除"并可从同一入口恢复。

## 9.8 技能失联或更名

- 消失：标"暂不可用"，成员关系保留，组合引用保留，其余技能不受影响。
- 更名：按旧名标失联，**不自动猜测**新名；用户可手动替换引用。
- 同名恢复：自动重新匹配并提示来源变化。

## 9.9 回滚

- 每次投影追加 **projection_log**（意图快照 + 结果 + 警告）。
- "回滚到上一次成功"是一等动作；P1 提供最近 N 次列表。
- 卸载插件不清除持久化数据。

# 11. 技术架构

## 11.1 形态

~~~text
zhiyin-plugin
├── host/            全局挂载：服务、存储、远程接口、设置页
│   ├── intent-service        意图 CRUD 与修订号
│   ├── catalog-observer      按 (cwd, scope) 观测 + 完整性状态
│   ├── projector             纯函数：Intent + Observed → Projection
│   ├── projection-log        发布记录与回滚
│   └── remote                Typert Remote 端点
│
├── surface/         受管 Agent 预设常驻组合内挂载：投影执行面
│   ├── skill-tool            同名 skill 工具（遮蔽默认消费者）
│   ├── catalog-publisher     pre-step 发布/退役目录
│   └── gesture               /name 手势解析
│
├── client/          Settings 页面：当前生效 / 技能包 / 全部技能 / 组合
│
└── shared/          类型、校验、并集与预算纯逻辑、locale
~~~

## 11.2 职责边界

- **host** 不知道任何 Agent 的具体目录；所有观测带 **cwd + scope**。
- **surface** 不做持久化写入，只读意图、发布投影。
- **projector** 无副作用、无 I/O、无时间依赖（时间由调用方注入），因此可单测、可重放。
- **client** 不直接访问 Node 侧；一切经 Remote。

## 11.3 投影契约

~~~ts
function project(input: {
  intent: EnsembleIntent
  packs: SkillPack[]
  scores: Score[]
  observed: { skills: NoteRef[]; complete: boolean; observedAt: string }
  scopeKey: string
  cwd?: string
  caps: { descriptionMaxLength: number; catalogCharBudget: number }
}): Projection
~~~

五步流水：**成员判定 → 闸门取交集 → 冲突检测 → 预算估算 → digest**。任何一步都不允许读取全局可变状态。

## 11.4 与上游消费者的语义对齐清单（parity）

接管意味着继承上游的行为契约，逐项必须有测试：

1. 目录只在**至少有一个模型可用技能**或观测不完整时发布。
2. 目录为持久 user-role 消息，**首个 pre-step** 建立，之后变化**追加** replacement。
3. 空集合追加显式空目录，**退役**旧名字。
4. **incomplete** 时发布已确认子集 + 警告 + 来源标记；恢复后即使条目相同也要重发。
5. digest 只对**条目 + 完整性**敏感，不因渲染差异重发。
6. **skill** 工具：非法名 / 未知名 / 不可模型调用，三种错误文案可区分。
7. **/name** 只扫描已认领的用户消息；未知名与用户禁用名保持普通文本。
8. 防重复加载：用户显式注入后，目录提示"不要再用工具加载同一技能"。

## 11.5 发布与变更

- 变更合并：UI 的多次开关进入"待提交"，一次"应用"产生**一次**投影与**一条**目录消息。
- 投影前算 digest，与上次发布一致则不发布（避免无意义追加）。
- 生效时刻记录在 projection_log；UI 显示"自 HH:mm:ss 起生效（下一模型步骤）"。
- 不承诺回溯已组装的请求。

## 11.6 事件与一致性

- 监听 **skills/change**：不带差异，必须重取快照；不得据事件猜测增删。
- 自身投影**不写注册表**，因此不会自造 **skills/change** 环（这是选 Consumer 而非 Provider 的直接收益）。
- 对快速连续的文件变化做合并/去抖，但不得延迟到下次重启。
- **complete:false** → 保留 last-known-good，标记 degraded，重试。
- 多个 Agent 各自独立投影，共享同一意图但各自观测。

## 11.7 持久化与并发

- **ctx.storageDomain** 定义版本化域；**intent-service** 是意图的唯一写入者。
- 意图用 **revision** 做乐观并发校验；冲突时提示"别处已修改"，不静默覆盖。
- 投影可以重算；**不允许**把投影当作独立可写状态。
- 卸载时释放 Remote、监听器、surface 注册与 Domain 句柄；数据保留。

## 11.8 兼容性

- 首版仅声明经过测试的 DSH Web Profile 版本范围。
- 每次 DSH 升级跑：技能注册表读取、消费者遮蔽、目录 parity、存储迁移四组契约测试。
- 不绑定 DSH 内部文件路径、未公开组件或私有 RPC。
- 注册失败、存储不可用、插槽缺失 → 诊断提示 + 安全降级（退回只读）。

# 12. 安全、权限与边界

## 12.1 八条硬边界

1. **只管理，不拥有。** 只存名称引用、摘要快照、成员关系；不复制正文、不缓存正文。
2. **不改原文件。** 不写 frontmatter、不重命名、不创建 .disabled、不删除目录。
3. **不放宽源策略。** 最终状态恒为"合奏成员 ∧ 源允许"，只减不增。
4. **信任边界。** 浏览器不提交任意路径或可执行内容；写操作由宿主校验。
5. **不把不完整当完整。** **complete:false** 不触发清空或批量停用。
6. **稳定身份。** 规范名是调用身份；provider/source/path 只用于解释。
7. **删除有边界。** 删包不删技能；删组合不改当前生效；删启用中的包必须先算实际退出项。
8. **可回滚。** 每次投影留痕，失败回滚到上次成功。

## 12.2 明确不承诺的能力

| 不承诺 | 原因 | 用户可见处理 |
|---|---|---|
| GUI 斜杠菜单与当前生效完全一致 | 菜单由宿主服务读注册表（F6） | 菜单项标注"未在当前生效"；点击给出解释（P2 尝试覆盖） |
| 阻止其他可信消费者直接 **ctx.skills.get()** | 那是宿主内部行为，非产品生效面 | 文档说明"织音管的是对外生效面" |
| 对第三方消费者共存时的一方静默失效负责 | 同名工具遮蔽关系由安装顺序决定 | 安装检查 + 诊断页列出当前消费者 |
| 语义消解技能冲突 | 需要 LLM 判断，属非目标 | 只检测、只提示 |

# 14. 验收标准

## 14.1 语义（纯函数）

| 场景 | 输入 | 预期 |
|---|---|---|
| 单包启用 | A={a,b,c} | E={a,b,c} |
| 双包无重叠 | A={a,b}, B={c,d} | E={a,b,c,d} |
| 双包有重叠 | A={a,b,c}, B={b,c,d} | E={a,b,c,d}，b/c 各一次 |
| 停用有重叠的包 | 停 A，B 仍启用 | E={b,c,d} |
| 停用最后引用 | A={a,b}，无他包无常驻 | E=∅ |
| 常驻 | A={a,b}, R={c}，停 A | E={c} |
| 排除 | A={a,b}, X={b} | E={a} |
| 常驻与排除冲突 | R={b}, X={b} | E 不含 b；UI 报配置矛盾 |
| 包内移除共享技能 | A、B 均含 b，从 A 移除 | b 仍生效（B 引用） |
| 应用组合（替换） | 当前 A+B；组合 B+C | 精确为 B+C；排除集按规则保留 |
| 应用组合（叠加） | 当前 A；叠加 B+C | A+B+C |
| 冲突阻断 | A.conflictsWith=[B]，同时启用 | 阻断并列出冲突对 |
| 冲突确认 | 同上 + 显式确认 | 允许，写入 conflictAck |
| 预算估算 | 3 包共 40 技能 | 字符数 = Σmin(len,cap)+框架；与实测偏差 ≤5% |
| 技能失联 | 包引用 a，快照无 a | a 标缺失；成员关系保留；其他技能不受影响 |
| 同名来源切换 | 同名技能 provider 变化 | 按名称匹配；显示来源变更 |

## 14.2 投影与集成

- 生效技能出现在模型目录，且**只出现一次**（跨包共享）。
- 未启用技能不出现在目录，**skill** 工具明确拒绝。
- 保留技能加载后正文完整、**resourceBase** 相对资源可解析。
- **/name** 对已启用且用户可调用的技能生效；对停用技能无效且不报错刷屏。
- 连续 6 次开关合并为一次应用时，会话中只追加**一条**目录。
- 空合奏追加空目录并退役旧名。
- 观测不完整时发布子集 + 警告，不批量停用。
- GUI 菜单中已停用技能被点击时，给出明确解释（不静默失败）。

## 14.3 parity 回归（对照 §11.4）

八条 parity 逐条有用例；其中 2/3/4/6 必须有"与上游行为等价"的对照测试。

## 14.4 UI 与恢复

- 多包可同时亮起，且"待提交"与"已生效"两态可辨。
- 共享技能只计一次并展示全部提供者。
- 停用共享包时预览正确区分退出与保留。
- 组合应用默认替换，叠加为独立动作且文案不同。

# 16. 风险与待决事项

| 风险 | 影响 | 处理 |
|---|---|---|
| 同名工具遮蔽不稳定或被上游改变 | 主路失效 | M0 Q1 + 契约测试；失败转 B2 |
| 上游消费者语义变化 | 目录行为漂移 | parity 清单 + 版本矩阵 + 升级回归 |

## 16.1 首版不可协商的产品决策

1. **包不是互斥角色**：多包可同时启用。
2. **共享技能不是重复技能**：关系可重复，生效只一次。
3. **停用包不得批量关闭成员**：必须重算并集。
4. **组合默认替换**，叠加是另一个明确动作。
5. **技能本体不归织音**：不复制、不改写、不删除。
6. **源策略不可被放宽**：取交集，只减不增。
7. **首次安装不改动任何可用性**，接管必须显式。
8. **无法控制的生效面必须标出来**，不允许用"已启用"掩盖。
9. **意图是唯一可写对象**，投影是纯函数，观测只读。
10. **预算与冲突是一等功能**，不是提示语。

# 附录 C：待决策清单（Decision Register）

**读法：** 每条只给一个推荐，不列“两条路都行”。推荐后面写**被推翻的条件**——那不是免责声明，是给下一个窗口的验证指令：条件被证据满足时，推荐就该改，不必回来问我。

**三条元规则：**

1. **沉默即默认。** 没人拍板时，按“推荐（沉默即此）”执行，不阻塞开发。
2. **拍板要回填。** 决策定案后回填 §0（DR 编号顺延），并检查是否要动 §16.1。只在聊天里定，等于没定。
3. **保守优先。** 两个方案难分高下时，选**可逆、可解释、不静默丢东西**的那个。

这五条各自锁死一个不可逆结构：谁有权改目录、目录何时变、排除存在哪、超限怎么办、导出承诺什么。定错要重写 schema 或重做交互；其余十九条定错，代价是改一段文案或加一个按钮。

## C.9 不建议在本版决定的事

- **云端同步与团队共享。** DSH 当前没有对应账户与权限模型，现在设计等于给一台不存在的服务器写协议。
- **自动推荐“该启用哪些包”。** 没有真实数据前，推荐只是噪音，还会掩盖用户自己的判断。
- **语义级技能去重（判断两个技能是不是同一件事）。** 不可判定，误判会删掉用户真正需要的能力。
