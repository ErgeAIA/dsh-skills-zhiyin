# dsh-market 市场页参考（技能市场的设计借鉴）

dsh-market 装的是**插件**，织音装的是**技能**；它支持**插件分组**，我们对应**技能包**。
下面是可复用的结构结论，以及逐条落到织音设置页的改法。

## 1. 页面五层骨架（顺序即认知顺序）

| 层 | dsh-market | 作用 |
|---|---|---|
| 1 页头 | 标题「插件市场」+ 副标题 + 右上「打开配置文件」 | 这是哪、能给什么 |
| 2 元信息条 | `dsh-market v1.73.20` · 申请收录 ↗ · 导出日志 ｜ 右：主按钮「全部更新 (1)」+ 弱化「重启前都不再提醒」 | 版本、出口、批量动作 |
| 3 标签页 | 发现 ｜ 主题 ｜ 收藏 (6) ｜ 已安装 (14)• ｜ 已屏蔽 ｜ 高级 | 处于哪个集合，计数内联，当前项下划线 |
| 4 折叠块 + 告警 | `▸ 更新检查 发现 1 个可用更新` + 灰底 callout 点名冲突包 | 异常先于内容 |
| 5 工具条 + 内容 | `[列表｜分组]` 分段 · 搜索（占满剩余）· 右「排序」｜ 2 列卡片 | 怎么找、怎么看 |

三条硬规律：
1. 同屏只有一个实心主按钮，其余为描边按钮或纯文字链接（三级动作）。
2. 计数挂在标签上，不做一整排统计卡。
3. 告警在内容之上、可折叠、点名具体对象。

## 2. 卡片解剖

1. 标题行：包名等宽字体 + 行尾 `…` 溢出菜单（位置固定）。
2. 版本/来源行：小一号、灰。
3. 描述：两行截断。
4. 次要动作行：纯文字（`+ 添加备注`、`有新版本 v0.7.5 · 更新内容 ›`）。
5. 底部状态行：左 `● 已启用`（色点+文字）+ 开关；右 `更新 v0.7.5` / 灰字「已是最新」。

## 3. 列表 / 分组 双视图与分组模型（源码 src/groups.ts）

```ts
type GroupAction = 'create' | 'rename' | 'delete' | 'set-members' | 'toggle'
interface GroupState { groups: Record<string, string[]>; groupOrder: string[] }
```

- 分组只持久化**成员名单**与**顺序**，**分组本身不存开关**：整组开关 = 批量改成员状态，分组显示状态由成员派生。
- 成员必须来自「已安装」集合；`set-members` 剪掉已卸载的幽灵名、去重；互斥资源（主题）一组最多一个。
- 包名规则：1–40 字符，允许中日韩、空格、下划线、连字符；重名拒绝。
- 已知坑（#964）：`groupOrder` 中残留、`groups` 中已不存在的孤立名字，会导致该行无法删除 —— 删除需能清理孤立项。
- 思路来源写明是 Claude Desktop 的技能管理：按能力分组、整组一键切换。

## 4. 手感细节

- 搜索 250ms 防抖，只提交「落定」查询；清空按钮清草稿而非已提交值。
- 排序偏好存 **localStorage**（每列表独立 field+dir），**不写 state.json**：排序属于浏览器，不属于共享状态。
- 已安装列表排序项：默认 / 名称 / 最新 / 最早。

## 5. 落到织音（改法清单）

1. 页头：`织音` + 副标题 + 右上「导出配置 / 导入配置」。
2. 元信息条：`@local/dsh-zhiyin-proto v0.1.0` · 观测时间 ｜ 右：主按钮「全部停用 / 全部启用」。
3. 标签页替代分段控件：`技能 (175) ｜ 技能包 (3) ｜ 组合（后续）`。
4. 告警区上移：目录超预算、同名冲突、包内引用了未安装技能 —— 内容上方 callout。
5. 工具条：`[卡片｜列表]` 分段 · 搜索（占满）· 右侧排序（名称/来源/字符数/启用状态）。
6. 技能卡：等宽技能名 + `…`；来源徽标 + 字符数；两行描述；底部 `● 已启用` + 开关；行尾图标动作（归档/详情）。
7. 技能包卡：包名 + `成员 N` + 三态徽标（全部启用/部分启用/全部停用）+ 成员预览前 6 + `…`（改名/复制/删除/管理成员）+ 行尾整组开关；页头 `+ 新建` / `导入 txt`。
8. 数据模型：保留 `packs:[{id,name,enabled,members,order}]`（包有独立开关）；吸收它的「三态由成员派生显示」「成员剪幽灵名并去重」「包名规则」「删除清理孤立项」四条。

## 6. 技能包语义（已与用户确认，2026-11-19）

- **包有独立开关**，不是纯批量动作。
- **并集 = 去重后的名单**：同时启用多个包时，生效集合是各包成员名单的去重并集；这个集合决定 Agent 可调用的技能。
- **一个技能属于多个包时，只有最后一个启用的包被关掉，该技能才真正停用**（任一所属包启用即视为启用）。
- **不向用户解释「并集」**：UI 只呈现「这个包包含哪些技能、开关后什么效果」；实现细节写进 README 的「效果说明」即可。
